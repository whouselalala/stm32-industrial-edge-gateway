工业物联网边缘网关（STM32F4 + FreeRTOS + LVGL）
项目简介
本项目基于 STM32F407 主控芯片，搭配 FreeRTOS 实时操作系统、LVGL 图形引擎，结合 ESP8266 Wi-Fi 模块、RS485 总线、W25Q64 SPI Flash 存储，打造一套工业级环境监测边缘网关。实现 Modbus-RTU 多传感器采集、本地触控可视化、MQTT 云端上报、断网离线缓存、自动重连与补传、系统运行日志、独立看门狗故障自复位、智能息屏等完整功能，对接巴法云物联网平台，适用于机房、温室、工业车间等无人值守场景。

版本迭代：第一版实现基础采集、上云、手动重连与手动补传；第二版新增Flash 标准化分区（4MB日志区+4MB缓存区）、系统日志、独立看门狗、低功耗息屏、日志浏览界面、自动重连与自动补传，工业可靠性全面提升。

三、核心功能实现
1. 手写 Modbus-RTU 协议栈
双CRC16算法：实现按位计算与查表法，查表法提速约8倍。

03功能码帧构建与解析：地址+功能码+寄存器地址+寄存器数量+CRC。

底层接收优化：直接操作 USART 寄存器，手动轮询 RXNE 标志，双重超时保护（帧间隔50ms，绝对超时800ms），杜绝 HAL 阻塞。

多从机支持：结构体数组管理（地址、寄存器、数据值），轻松扩展设备。

2. 手写 MQTT 3.1.1 协议栈
手动构建二进制帧：CONNECT、SUBSCRIBE、PUBLISH、PINGREQ 全部手写，不依赖第三方库。

变长剩余长度编码：符合 MQTT 规范，支持大于127字节的报文。

联网流程：ESP8266 AT 配网 → TCP 透传模式 → MQTT 登录 → 订阅主题 stm32。

自动重连（第二版新增）：心跳检测连续失败后自动调用 RE_MQTT_Init 恢复连接，无需人工复位。

3. SPI Flash 分区管理 & 断网续传
8MB 分区规划：前4MB = 系统运行日志区，后4MB = 离线数据缓存区。

环形缓存机制：每条记录128字节（魔数+时间戳+数据长度+JSON载荷），写满自动回绕。

断电续写：上电扫描缓存区，定位最后有效写入地址，不丢失未补传数据。

逻辑删除：补传成功后仅改写魔数（0xDEADBEEF → 0xFFFFFFFF），不擦除扇区，延长 Flash 寿命。

自动补传（第二版新增）：网络恢复后，MQTT任务自动分批补传（每次最多5条，间隔800ms），无需手动干预。

4. 系统运行日志（第二版新增）
独立日志分区：存储结构化日志（时间戳、等级、内容），写满自动循环覆盖。

统一接口：Log_Write(level, str) 全工程可调用，记录网络状态、通信异常、设备事件。

LVGL 日志页面：点击主界面右上角“日志”按钮，倒序读取 Flash 日志（最新在上，最多30条），支持返回主界面。

应用价值：运维人员可现场查看历史故障，无需外接串口。

5. 网络可靠性机制
心跳检测：AT 任务每10秒发送 PINGREQ，等待 PINGRESP（1秒超时），连续3次失败则判定离线。

离线缓存：MQTT 任务检测到 g_mqtt_connected == 0 时，自动将 JSON 数据写入缓存区。

自动重连 + 自动补传：断网后心跳任务自动执行 RE_MQTT_Init 恢复连接；连接成功后 MQTT 任务自动触发分批补传，全程无人工干预。

6. 系统高可靠（独立看门狗）
启用 STM32 独立看门狗 (IWDG)，溢出时间 20 秒。

专属高优先级喂狗任务，每 3 秒喂狗一次。

系统卡死、任务死锁时，看门狗自动触发硬件复位，实现故障自愈。

7. LVGL 图形界面 & 低功耗息屏
主监控页：温度、湿度、光照三个卡片 + 进度条 + 底部状态栏（在线状态/运行时间）。

日志页：列表显示最近日志，倒序，新日志置顶，可点击“返回”按钮回到主界面。

按需刷新：仅数据变化或状态变化时更新控件，避免无效重绘，降低 CPU 占用。

智能息屏：10 秒无操作（触摸/数据变化）自动关闭 LCD 背光，数据变化或触摸时立即亮屏，降低整机功耗。

四、踩坑记录与解决方案
问题现象	根因分析	解决方案
Modbus 接收全0	RS485 A/B 线极性接反	对调总线 A、B 接线，增加终端电阻
MQTT 连接返回错误码	CONNECT 报文剩余长度计算错误	逐字节重算，修正报文长度
透传模式 > 匹配失败	逐行解析不鲁棒	改用原始字节流滑动匹配
心跳检测卡死	持锁期间等待 PINGRESP 形成死锁	拆分逻辑，缩短持锁时间
补传仅发一条	读写指针或魔数逻辑错误	优化指针移动与魔数状态机

MQTT 重连失败	重连流程误关闭 TCP 连接	重连时只发 AT+CIPSTART，不做关闭操作

UI 卡死	UI 刷新过于频繁	改为数据变化才刷新，降低刷新率
五、快速使用指南
1. 硬件接线
严格按引脚表连接；ESP8266 独立供电（勿从 STM32 取电）；RS485 A+/B- 之间并联 120Ω 终端电阻；所有设备共地。

2. 固件要求
ESP8266：烧录 NonOS AT V1.7.5 固件，确保支持透传模式。

STM32：使用 Keil MDK 编译并烧录本项目。

3. 云平台配置
注册 巴法云，创建设备主题 stm32。

在代码中替换 Wi-Fi 名称、密码、设备 UID。

4. 运行与测试
上电：自动初始化 → 多任务启动 → 配网 → MQTT 登录 → 订阅主题。

正常模式：传感器采集 → 界面刷新 → 数据上报云端。

断网测试：断开 WiFi，设备离线，数据写入 Flash；恢复网络后设备自动重连并补传缓存数据（无需复位）。
